Cierre de la unidad

📑 Resumen

  • Un sistema es un conjunto de componentes que interactúan entre sí dentro de un entorno para alcanzar un objetivo común.
  • Los sistemas de información cumplen funciones clave en la gestión organizacional.
  • El Ciclo de Vida del Desarrollo de Software (SDLC) se compone de siete fases: planificación, análisis, diseño, desarrollo, pruebas, implementación y mantenimiento.
  • Existen distintas metodologías para implementar el SDLC, como:
    • Cascada: adecuada para proyectos pequeños y estables.
    • Espiral: útil en proyectos grandes con alto riesgo.
    • RUP: orientada a desarrollos formales de complejidad media a alta.
    • Metodologías ágiles: pensadas para entornos cambiantes y colaborativos.
  • Las buenas prácticas en el desarrollo de software incluyen el uso de diagramas UML, la trazabilidad de requisitos y la gestión de cambios.
  • La ingeniería de requerimientos permite alinear las necesidades del cliente con lo que el equipo de desarrollo puede construir.
  • Los requerimientos del sistema se clasifican en funcionales (qué debe hacer el sistema) y no funcionales (cómo debe comportarse).
  • Las técnicas para el levantamiento de requerimientos incluyen entrevistas, talleres, observación, análisis documental, encuestas y uso de prototipos. 
    La Especificación de Requerimientos de Software (ERS o SRS) consolida toda la información recogida y actúa como documento de acuerdo entre los interesados.
  • La Matriz de Trazabilidad de Requerimientos (MTR) asegura la cobertura de requerimientos, permite rastrear su origen, vincularlos con otros elementos del proyecto y gestionar cambios. .
