📑 Resumen

  • La arquitectura de software define la estructura de un sistema, sus componentes y cómo se relacionan. Puede ser monolítica, organizada en n-capas o basada en microservicios. Una buena elección reduce costos, mejora la colaboración, aumenta la resiliencia, aunque también puede incrementar la complejidad.
  • Los estándares de programación garantizan consistencia y calidad del código. Buscan que sea legible, mantenible y colaborativo. La nomenclatura descriptiva es clave: usar camelCase o PascalCase hace que el código sea más claro y predecible.
  • Los comentarios deben explicar el “porqué” de las decisiones, no repetir el código. La documentación formal (como Javadoc o docstrings) facilita que otros usen el código de forma correcta.
  • El manejo de errores requiere una estrategia clara: capturar excepciones, registrar los fallos y dar mensajes útiles tanto para usuarios como para desarrolladores.
